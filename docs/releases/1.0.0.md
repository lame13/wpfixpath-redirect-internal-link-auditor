# IndexLane 1.0.0

Find the broken link, fix it where it is stored, and check the result—all from WordPress.

Version 1.0.0 adds link repairs and scheduled checks to IndexLane's existing scan reports. It's free, with no account or external scanning service required.

## Preview a repair, then apply it

Enter a replacement URL under **Fix links** to see the affected sources and their full before-and-after values. Apply the change when it looks right. If a source changes after the preview, you'll need to preview it again.

Repairs support stored content, Navigation links, synced patterns, database-backed templates, classic menu custom links, and assigned block widgets. Theme files, object-backed menu links, and other unsupported storage still need their own editors. IndexLane never creates redirect rules.

**Recent repairs** keeps undo evidence for up to 25 repairs within an 8 MB total budget. Undo skips content edited since the repair; a partially undone batch can be retried. Older repairs leave the history as it fills up, so keep your usual backups.

## Check the result and watch for changes

Save a scan before editing, then use **Check fixes against saved scan** to see what changed. The comparison and CSV distinguish new, changed, resolved, and still-present issues.

Turn on an hourly, twice-daily, daily, or weekly WP-Cron check to keep watching the selected sources. The first complete run sends a summary. Later emails report newly detected or resolved problems; acknowledged issues stay in the evidence without triggering change notifications.

Request-limited scans are marked partial. They don't replace the last complete comparison or claim that unseen problems have been fixed. Dashboard and Site Health status show when a check needs attention.

## Run the same workflow from WP-CLI

```sh
wp indexlane scan --content-scope=all --format=json
wp indexlane fix --from=https://example.com/old/ --to=https://example.com/new/ --dry-run
wp indexlane fix --from=https://example.com/old/ --to=https://example.com/new/ --yes
wp indexlane repairs
wp indexlane undo --yes
```

JSON and CSV output are suitable for scripts. A repair requires a complete scan; increase the request limit or narrow the scope if it stops early.

## Fixes included in this release

- Restricted replacements to supported HTML link attributes and block link settings, leaving scripts, comments, text, and unrelated attributes alone.
- Preserved backslashes and block JSON through WordPress writes and undo.
- Corrected duplicate replacement counts and rejected custom-provider storage that could be mistaken for a post.
- Bound confirmation to the exact preview and saved undo evidence before content writes.
- Corrected partial monitor results, CLI output, and retrying partial undo.

The WordPress.org listing is now **IndexLane Broken Link & Redirect Auditor**. The slug, text domain, and existing saved-scan format are unchanged. Scans leave content unchanged, and scheduled checks stay off until you enable them.
