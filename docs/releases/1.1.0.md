# IndexLane 1.1.0

Review every suggested fix at once, apply the ones you keep, and undo the whole batch in one step.

Version 1.1.0 builds on 1.0.0's in-place repairs. It adds a reviewed batch for the links the scan already knows how to fix, and it extends **Page intent** with two more checks for links that respond successfully but still point somewhere wrong.

## Apply suggested fixes as one batch

When a scan already suggests a replacement for several URLs, select **Review suggested fixes** under **Fix links**. Every stored URL and its suggested replacement appears together, with a checkbox to keep or clear each one. The preview shows the exact before-and-after stored value for every affected source, and a source that contains more than one suggested URL is written once.

Select **Update preview** after changing the selection, then **Apply changes**. The whole batch is recorded as a single entry in **Recent repairs**, so one **Undo** restores every source. As before, a source edited after the preview is skipped rather than overwritten, and a repair still touches only complete link attributes and supported block link settings.

## Two more links that respond but still need attention

- A stored link that uses a different scheme than the site address, such as an `http://` link on an `https://` site.
- A stored link whose trailing slash differs from the address WordPress serves for the content it resolves to.

Both appear beside the HTTP result under **Page intent**, both only apply to a healthy response that did not redirect, and both offer a suggested replacement you can review and apply. Neither adds an outbound request.

## Run the same batch from WP-CLI

```sh
wp indexlane fix-suggested --dry-run
wp indexlane fix-suggested --from=https://example.com/old/,https://example.com/older/ --yes
wp indexlane repairs
wp indexlane undo --yes
```

`fix-suggested` scans the same selected sources, builds the same reviewed batch, and prints the batch ID and the command that undoes it. `--dry-run` previews the exact changes without writing anything.

## Fixes and behavior in this release

- Folded repairs for a source that contains several suggested URLs into one write, so the source is not written once per URL.
- Kept a linked section when suggesting a permalink, so a repair never drops a stored fragment.
- Only report a scheme or trailing-slash difference on a healthy, directly served response; a redirected or broken link keeps its transport outcome.
- Bound the batch confirmation to the exact previewed plan and selection, and refused a changed source rather than overwriting it.

Scans and scheduled checks still leave your content unchanged, and scheduled checks stay off until you enable them.
